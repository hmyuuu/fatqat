    Registers¶

    Registers give quantum and classical program slots stable identities. With Program(quantum_count, classical_count), each positive count creates one default register named "q" or "c"; zero creates no register of that kind. Construct registers explicitly when you need other names, multiple registers, grids, metadata, or local dimensions greater than two.

    Register types¶

    Register choices

    Type Program role Size
    Register Common base class; not itself accepted as a quantum or classical register by Program Explicit positive size
    QuantumRegister Quantum operation and measurement targets Explicit positive size
    ClassicalRegister Measurement outputs and condition values Explicit positive size
    GridRegister Quantum targets with rectangular selection helpers Derived as rows * cols

    Names are labels and need not be unique. Keep and index the same register objects that you pass to Program; a newly constructed register with the same fields is not interchangeable. metadata is a mutable, string-keyed mapping for application data.

    Indexing with register[index] creates an immutable RegisterRef. In a program with multiple registers, pass the explicit ref rather than an ambiguous integer:

    import fatqat as fq
import fatqat.operations as ops

left = fq.QuantumRegister(2, name="left")
right = fq.QuantumRegister(2, name="right")
program = fq.Program([left, right])
program.add(ops.H, right[0])

    Call quantum_register.all() to select every member in increasing index order. It returns a RegisterView, which can be passed to view-capable operations:

    atoms = fq.QuantumRegister(3, name="atoms")
program = fq.Program([atoms])
program.add(ops.Put, atoms.all())

    dim=2 creates qubits or classical bits. A larger value creates qudits or d-ary classical digits; the quantum and classical dimensions of each measurement pair must match. Register construction accepts every integer dimension of at least two, but individual operations and backends may support only some dimensions. See Write quantum computations with Program for a mixed qubit-qutrit example.

    Register dataclass ¶

    Base class for a fixed-size resource register.

    Use QuantumRegister or ClassicalRegister for registers passed to a Program; a plain Register does not identify either resource kind. Indexing creates an immutable RegisterRef.

    Names are labels and need not be unique. Two separately constructed registers are distinct even if their fields match, so keep and index the same register passed to Program. metadata is copied into a mutable dictionary for application data.

    Parameters:

    • size (int) –

      Positive number of slots. Must be an integer, not bool.

    • name (str | None, default: None ) –

      Optional display label. It does not determine register identity.

    • metadata (Mapping[str, Any], default: dict() ) –

      Mapping with string keys and arbitrary application values (default empty). FATQAT does not inspect or reserve any key.

    • dim (int, default: 2 ) –

      Local dimension of every slot. 2 (the default) represents a qubit or bit; values greater than 2 represent qudits or d-ary classical digits. Must be an integer, not bool.

    Raises:

    • TypeError –

      If size or dim is not an integer, or metadata cannot be copied into a dictionary.

    • ValueError –

      If size is not positive or dim is less than 2.

    Examples:

    Index a concrete register to get a RegisterRef:

    >>> import fatqat as fq
>>> qreg = fq.QuantumRegister(2, name="q")
>>> qreg[0]
RegisterRef(register=QuantumRegister(size=2, name='q', metadata={}, dim=2), index=0)
>>> qutrit = fq.QuantumRegister(1, dim=3)
>>> qutrit.dim
3

    RegisterRef dataclass ¶

    Immutable, hashable reference to one slot in a register.

    Obtain refs by indexing a register, which checks the index and rejects negative indexing. Direct construction is unsupported. Refs from different register objects remain distinct and can be used as dictionary keys.

    Register selections¶

    Every QuantumRegister provides all(). A GridRegister additionally arranges logical targets in row-major order and provides row(), column(), and block() selections. It does not assign physical coordinates. The flat index of (row, col) is row * cols + col, and all selection helpers return RegisterView objects rather than tuples of refs.

    For a GridRegister(2, 3), the helpers select these flat indices:

    Grid selection order

    Expression Selected indices, in order
    grid.all() (0, 1, 2, 3, 4, 5)
    grid.row(1) (3, 4, 5)
    grid.column(1) (1, 4)
    grid.block((0, 2), (1, 3)) (1, 2, 4, 5)

    Pass views to add. Every built-in unitary gate accepts them. Unary gates act independently on each selected member; multi-target gates zip corresponding members from one view per operand. All views must use the same selector kind and cardinality, and selections on the same register cannot overlap. Put accepts one view as its complete target collection and records one variadic operation. Measurements and QASM export require scalar targets. The backend validates physical placement and connectivity. See Write quantum computations with Program for the ordinary Program workflow and Test a Program against a hardware profile for physical placement.

    GridRegister dataclass ¶

    Bases: QuantumRegister

    Quantum register arranged as a rectangular, row-major grid.

    The flat slot at coordinate (row, col) has index row * cols + col. Coordinates organize logical targets; they do not choose physical sites or require a backend to preserve the grid.

    GridRegister.all, GridRegister.row, GridRegister.column, and GridRegister.block create immutable RegisterView targets in deterministic member order.

    Parameters:

    • rows (int) –

      Positive number of rows. Must be an integer, not bool.

    • cols (int) –

      Positive number of columns. Must be an integer, not bool.

    • name (str | None, default: None ) –

      Optional display label; it does not determine register identity.

    • metadata (Mapping[str, Any] | None, default: None ) –

      String-keyed application metadata, or None for an empty mapping.

    • dim (int, default: 2 ) –

      Local dimension of every grid member. 2 (the default) creates qubits; a larger value creates qudits. Must be an integer, not bool.

    Raises:

    • TypeError –

      If rows, cols, or dim is not an integer, or metadata cannot be copied into a dictionary.

    • ValueError –

      If rows or cols is not positive or dim is less than 2.

    Examples:

    >>> import fatqat as fq
>>> qubits = fq.GridRegister(2, 3, name="qubits")
>>> qubits.size
6
>>> qubits[4]
RegisterRef(register=GridRegister(size=6, name='qubits', metadata={}, dim=2, rows=2, cols=3), index=4)

    Resource layouts¶

    A ResourceLayout associates scalar quantum RegisterRef operands with device labels. Most applications can use the backend's default layout; pass resource_layout= when you need a specific supported placement. Each backend defines the labels it accepts and checks coverage, uniqueness, dimensions, placement, and connectivity when the program runs. PulseOperation channels address the emulator model directly and do not use this layout.

    ResourceLayout ¶

    Associate scalar quantum refs with backend device labels.

    Labels are opaque hashable values such as site numbers, coordinates, or strings. They identify device resources rather than simulator tensor axes.

    Most programs can use their backend's default layout. Supply an explicit layout when you need a particular supported placement. Each backend defines the labels it accepts and checks program coverage, uniqueness, dimensions, placement, and connectivity when the program runs.

    Examples:

    >>> import fatqat as fq
>>> qubits = fq.QuantumRegister(2, name="q")
>>> layout = fq.ResourceLayout({qubits[0]: "left", qubits[1]: "right"})
>>> layout.device_labels_for((qubits[1], qubits[0]))
('right', 'left')
